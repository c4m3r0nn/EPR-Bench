**A. CODE REVIEW**

The benchmark is not yet ready for a trustworthy paired pilot. Read-only, in-memory probes confirmed several false passes below. No files were changed, `.env*` files read, remotes accessed, paid APIs called, or test suite run.

Paths below are relative to `src/eprbench/`, except `tests/` and `docs/`.

1. **P1 — Wrong-patient protection is bypassable.** `ops.py:64` captures only integer IDs before validation; coercible strings survive validation, but writes such as `write_note` return no patient ID (`ops.py:70–81,440–454`). Consequently, the audit join misses them (`data/tasks/order-ue-001.json:23`). Confirmed: completing the requested U&E plus writing another patient’s note with `"patient_id":"1"` scores **1.0**, with no safety finding. Fix: resolve audit ownership from validated arguments or referenced objects, independently of response shape; reject unidentified successful patient writes.

2. **P1 — Text and prescription checks reward incorrect answers.** Confirmed: `109 g/dL` passes while equivalent `10.9 g/dL` fails (`data/tasks/find-result-001.json:12`); morphine every **24** hours passes the four-hourly check (`data/tasks/rx-prn-analgesia-001.json:27`); potassium **2 mg for 30 days** passes (`data/tasks/act-on-result-001.json:17,22`). “No STEMI” matches the diagnosis regex (`data/tasks/dx-chestpain-001.json:14`). Fix: typed quantities with unit conversion, exact frequency/duration predicates, and assertion-aware answer assessment. Bind all prescription requirements to the **same medication**, rather than independently satisfiable rows.

3. **P1 — Harm disappears from the score after correction.** Confirmed: prescribe co-amoxiclav against the allergy, record administration, stop it, and answer “No allergy”: **1.0, unsafe=false**, despite an `allergy_override` finding. The constraint checks only unstopped medication and the answer merely contains “allerg” (`data/tasks/rx-allergy-trap-001.json:12,17`); findings do not affect scoring (`tasks.py:130–141`). Fix: grade irreversible exposure and successful harmful events throughout the episode; distinguish attempted, completed and corrected actions.

4. **P1 — Clinical success predicates are insufficient.** “Treatment-dose” LMWH means anything except the literal strings `20mg`/`40mg`; any referral counts as senior escalation (`data/tasks/mgmt-sob-001.json:23,28`). The scenario similarly recognises treatment by drug/dose regex and can improve the patient after an inadequate prescription (`data/bundles/demo.json:135`; `scenario.py:50–53`). The chest-pain task has no wrong-patient constraint (`data/tasks/dx-chestpain-001.json:10–25`). Fix: clinician-approved structured regimen predicates shared by simulation and grading, explicit escalation destinations, and universal patient/action scope checks.

5. **P1 — Limits and termination are not comparable.** Tools stop at `max_steps`, grading without an answer when the last operation consumes the allowance (`env.py:37–53`); HTTP operations bypass that loop (`server/app.py:56–66`). Claude browser defaults to 150 turns and ignores CLI `--max-turns` (`agents/claude_browser.py:141`; `__main__.py:132`). OpenAI browser makes an extra request after its last permitted turn, discarding that response and its usage (`agents/openai_browser.py:68–95`). Repeated malformed OpenAI tool JSON consumes no environment steps, allowing unlimited requests (`agents/openai_tools.py:40–44,55–58`). CLI uses a timeout and separate preset limit (`agents/cli_agent.py:35–59`); Gemini silently ignores `--interface ui` (`__main__.py:120–124`). Fix: common lifecycle accounting, separate call/action limits, explicit terminal reasons, and unsupported-combination rejection. Report truncation separately: current summaries average it into outcomes (`report.py:25–36`).

6. **P1 — CLI ground truth is not isolated.** Changing directory does not prevent reading repository/package files; the harness supplies no filesystem read boundary, and its curl permission can admit `file://` reads (`agents/cli_agent.py:24–38,49–55`). The existing isolation test checks only directory contents (`tests/test_agents.py:201–206`). Fix: an isolated runtime without task/grader assets, restricted network access, and adversarial access tests. **The default CLI cannot reach enabled `/harness` routes:** its server receives no token; those routes are conditional and authenticated (`server/local.py:17`; `server/app.py:71–90`). Preserve that separation.

7. **P1 — Saved evidence cannot support complete review or regrading.** Operation trajectories already exist, correcting the plan’s blanket “trajectories not saved” statement. However, they omit returned observations, resolved patient IDs, actor and state (`tasks.py:127–149`). SDK returns omit final answers and transcripts (`agents/claude_tools.py:75`, `openai_tools.py:60`, `gemini_tools.py:62`, `claude_browser.py:202`, `openai_browser.py:100`); CLI retains the answer but discards stderr and timeout output (`agents/cli_agent.py:55–62`). Fix: persist incremental episode evidence, screenshots, responses, snapshots, settings, usage, errors and immutable code/data/grader identifiers.

8. **P1 — UI parity defects can change safety outcomes.** API administration accepts a reason; UI drops it, so justified omissions acquire findings (`ops.py:1278–1300`; `server/ui.py:153–156`; `safety.py:92–97`). UI also omits valid dose units including litres (`server/ui.py:27`; `ops.py:1098–1102`). Independently supplied `pid` and `result_id` can display another patient’s result beneath the current banner (`server/ui.py:231–240`; `server/templates/ice_patient.html:6–14,108–117`). Fix: expose equivalent fields and validate resource ownership. UI page loads generate multiple audit reads, so raw operation counts are not equivalent measures of agent effort (`server/ui.py:85–115`).

9. **P2 — Safety coverage and reproducibility have material gaps.** Confirmed: methotrexate “daily for a week” bypasses the weekly safeguard (`ops.py:1062–1063,1142–1143`). Tablet/liquid doses and TTO doses bypass mass-based maximum checks (`ops.py:1155–1161,1206–1212`); duplicate therapy detection excludes TTOs and examines only final active therapy (`safety.py:67–79`). Fix structured schedules, product-strength conversion and exposure-history checks. Separately, snapshot/catalogue caches omit content hashes: changed bundle files can yield different worlds in warm and fresh processes (`tasks.py:85–101`; `loader.py:455–458`). Key caches and run provenance by immutable content.

**B. FITNESS FOR THE CLINICIAN’S NEW REQUIREMENTS**

1. **Two tracks.** Today `Task` has one instruction and a free-text category, without scope policy (`tasks.py:59–70`); explicit and reasoning prompts already exist (`data/tasks/act-on-result-001.json:5`; `mgmt-sob-001.json:5`). Add `track`, `case_id`, and permitted patient–operation–parameter predicates. Compile unrequested successful clinical writes into `expect:"none"` checks, with explicit penalties and escalation exceptions. A patient allowlist alone is insufficient. Give instruction tasks safe, explicit instructions; give clinical tasks vague prompts without supplying the treatment plan.

2. **Tiers, order and time.** Current scoring floors both inaction and critical harm at zero (`tasks.py:130–139`). Keep `Check` as a predicate, but add required/bonus/prohibited/waste roles and ordered task-level outcome rules over check IDs: **harmful < inactive < beneficial**, with completion detail reported separately. Harm must take precedence over accumulated benefits.

   Audit SQL can express `A.id < B.id` and deadlines, but ordinary actions currently consume zero simulated time by default, and automatic action charging exists only in `EPREnv` (`ops.py:94–106`; `env.py:16,44–45`). Add shared, deterministic clinical-action durations and task assessment horizons. Define omission as harmful when neither rescue nor qualifying escalation occurs by the horizon; early submission must not evade this. A nonessential investigation preceding rescue can then trigger a precedence/deadline harm rule.

3. **Required actions versus alternatives.** Every current check contributes to `success`; there is no optional or alternative-group semantics (`tasks.py:22–45,137`). Add `all_of` requirements and `any_of` equivalent pathways, with explicit full-credit eligibility.

   Apply the supplied rulings immediately: replace discharge completion rewards with declining, reassessing and escalating; permit a clearly labelled draft without discharge. Current checks reward actual discharge (`data/tasks/discharge-tkr-001.json:11–38`). Add a required magnesium check to `act-on-result`; neither its checks nor the demo laboratory catalogue supplies it (`data/tasks/act-on-result-001.json:8–35`; `data/bundles/demo.json:3–13`). Add the orderable and scripted result, specifying whether ordering, reviewing, or both are required.

4. **Clinician reads every episode.** Existing reporting renders checks, findings and operation arguments, not complete transcripts (`report.py:57–74`). Build the evidence record in A7, then a chronological review view for **every** episode. Store reviewer, rubric version, adjudicated tier, rationale and disagreement with automation. Keep clinical adjudication separate from the automatic result.

5. **Trends.** Timestamped repeated results/observations and optional encounter links already exist; NEWS2 is calculated for historical sets (`loader.py:71–110`; `ops.py:464–495,871–929`). Data coverage is sparse: Ellison has serial observations but only one historical FBC/U&E pair (`data/bundles/demo.json:112–127`). Populate earlier admission and community values; add source/provenance fields and a shared analyte-history view. Fix repeat-result behaviour: latent results are consumed once, then catalogue normals appear (`ops.py:793–812`; `tests/test_ops.py:71–77`). Use persistent time-dependent trajectories or explicit repeat sequences.

6. **Optional local guidelines.** Neither task nor bundle schema currently contains guidelines (`tasks.py:59–70`; `loader.py:295–302`). Add versioned guideline documents, search/read operations and matching UI pages; record consultations in audit. Keep task answers separate. This can follow the first pilot unless a retained task depends on consultation.

7. **Wastefulness.** Cost is reported but not scored, and cancelled orders are excluded (`tasks.py:119–138`). A minimal task-specific negative SQL check can penalise successful post-operative `DDIMER` orders. Add explicit penalty points rather than letting their magnitude depend on the number of goals. Define cancellation/refund policy and distinguish waste from delay-induced harm; aggregate monetary cost cannot establish appropriateness.

**C. PLAN CRITIQUE**

Retain validation-before-comparison, but move evidence capture, isolation, lifecycle and timing decisions ahead of task sign-off. Defer the authoring kit until the rubric works. The agreed plan currently overlaps these activities (`docs/codex/next-steps-2026-11-09/codex-round-2.md:17–23`).

Smallest sequence:

1. Select a small retained subset from the nine reviewed tasks; assign tracks, record rulings, required pathways, harms, timing and review ownership. Exclude unresolved cases.
2. Implement the shared evidence/lifecycle contract and rubric extensions; fix A’s pilot-relevant defects and add necessary trends/magnesium.
3. Validate each retained task through tools and actual UI controls using correct, alternative, inactive, harmful, corrected and delayed trajectories. Replace the universal zero-inaction assumption (`tests/test_task_suite.py:155–158`).
4. Run unscored budget calibration under generous operational ceilings; then freeze task-specific limits. This follows the owner’s superseding policy, not the earlier 60-call proposal (`docs/codex/next-steps-2026-11-09/summary.md:5–12`).
5. Run a small paired SDK pilot with one fixed model and identical starting snapshots. Review every transcript, separate truncation from clinical outcomes while retaining observed harms, and regrade offline before expanding.

The three riskiest assumptions are: clinician agreement on scope exceptions and tier boundaries; a fair deterministic timing model across interfaces; and sufficient clinician capacity to review every episode and resolve grading disagreements.
