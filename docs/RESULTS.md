# Results: the agent-CLI preview runs of 23 November 2026

Exploratory results from 60 episodes. They describe what two agent products did on three draft cases; they do not rank
models, and they say nothing about clinical safety. Read the caveats at the end before quoting a number.

**Which model Codex used.** Codex's own event stream does not name a model, so the harness records none. On the browser
route, though, every tool call Codex sent to the computer MCP server carried Codex's turn metadata, which names
`"model": "gpt-6.2-sol"` and `"reasoning_effort": "low"` (all 10 browser episodes, every call). On the API route nothing
in the evidence names the model. We report this as observed and unverified: it is what the client said about itself,
not something the harness controls, and the API runs may or may not have used the same model.

**Earlier runs are not included.** Development runs before these (a pilot on 2 October 2026, dry runs on 15 and
17 November, two paired runs on 21 November and smoke runs of the browser route) ran on code and cases that have since
changed: the grader and harness fixes from their audits, the capability map that gives both routes the same section
list (the 21 November audit found browser agents could not see the assessments entry), and the clinical lead's rulings
of 21 and 23 November. Their tiers would not be comparable, and some were cut short by subscription limits. They remain
development evidence; the audit of the 21 November run is in `docs/codex/paired-run-2026-11-21/codex-review.md`.

## Headline

All 60 episodes were submitted. Under the current marking 55 are complete and 5 partial; none is inactive and none
harmful. When the episodes ran, 51 were complete and 9 partial: the four Codex runs of the potassium judgement task
moved from partial to complete when the minimum interval before the recheck became 4 hours (AI-proposed, D-A05 in
docs/CLINICAL_DECISIONS.md). No other episode changed tier, and every graded world was reproduced byte for byte.

All five partials are on the browser route (four Claude Code + Sonnet, one Claude Code + Fable), and each missed one
structured entry: three never signed off last night's U&E in ICE, and two wrote no note or Wells form for the
reassessment their replies describe. With two repeats per cell this is a description of these runs, not evidence that
one route or product is better; the [walk-throughs](walkthroughs/) show what each run did.

## Caveats

- **A product, not a bare model.** Claude Code and Codex were measured as shipped: their own system prompts, loops,
  context handling and tools. A difference between them, or between their routes, is not a difference between models.
- **Two repeats are exploratory.** Two repeats per cell over five tasks on three synthetic cases support description, not
  inference; no interval or significance claim is made.
- **Unequal action units.** The API route charges one operation call; the browser route one mouse or keyboard action, and
  one page load runs several operations. Action counts are not comparable across routes; nor are their limits.
- **Simulated time is chosen by the agent.** An agent waits as long as it likes, so episodes ended at very different
  simulated times (60 to 260 minutes in the discharge case), changing which results, replies and deteriorations it saw.
- **Scripted staff.** Nurses, cardiology, the ED consultant and the orthopaedic registrar are scripted, with fixed delays;
  what an agent learns depends on when it stops.
- **Structured entries only.** The grader reads structured entries, never free text: a Wells score written in prose is
  credited only through the note rule (D-C02), and a reply that says a result was reviewed does not sign it off.
- **Screenshot delivery is not attention.** A screenshot's contents count as shown once its tool result reached the agent
  program; that does not show the model looked at or understood it.
- **Codex does not report its model** in its event stream (see above for what its browser-route metadata says).
- **Draft cases and marking.** The cases were written by the developer and reviewed by one clinician, the clinical lead.
  Several marking rules, including the three applied in this release, are AI-proposed and await clinician review
  (docs/CLINICAL_DECISIONS.md). "Complete" means the marked pathway was met, not that the care was complete or safe.
